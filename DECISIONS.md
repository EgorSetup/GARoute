## Технические решения категории B

### Q03-B. Неизвестная скорость и полнота данных — ACCEPTED / TECHNICAL

Сохранять исходное maxspeed. Однозначные числовые значения и явно указанные единицы переводить в км/ч; отсутствие, противоречивый список или нераспознанный текст отмечать unknown. Не назначать скорость по умолчанию, не удалять дорогу ради успешного расчёта. До расчёта проверить доступные рёбра выбранной области: при неизвестной обязательной скорости производственный запуск заблокировать с перечнем проблем; граф и диагностика остаются доступны. Это консервативная техническая обработка неопределённых данных, не транспортная модель. Автоматические подстановки потребуют нового решения. Для необязательных признаков штрафов хранить unknown отдельно от false/0; политика начисления относится к Q04-C.

**Уточнение Q03-B / VERIFY, 2026-11-02.** После T02.02 штатно задан вопрос исходному чату «План генетического маршрутизатора», ответ получен через `read_thread`. Чат предложил расшифровать `maxspeed=RU:urban` как 60 км/ч и модельно подставлять 30 км/ч при отсутствии maxspeed. [Документация OSM](https://wiki.openstreetmap.org/wiki/RU:Key:source:maxspeed) подтверждает соответствие символического `RU:urban` пределу 60 км/ч; это верхний предел, а не наблюдаемая средняя скорость. Поэтому точное значение `RU:urban` используется как **implicit_osm_verify** с сохранением исходного тега и правила преобразования. На реальном графе 2143 таких направленных ребра после учёта directional tags. Предложение 30 км/ч при отсутствующем теге **не применяется**, так как противоречит принятому правилу без автоматических подстановок; 170 рёбер остаются unknown. Разница с первоначальными 2140/176 объясняется направленными тегами: три `RU:urban` выбраны из directional maxspeed, шесть рёбер без общего maxspeed получили направленное числовое значение. Источник и проверка отмечены; это не историческое согласие пользователя и не универсальное толкование ПДД.

**Q03-C RESOLVED / VERIFY, 2026-11-04.** После замечания пользователя о блокировке 170 рёбер вопрос направлен в исходный ChatGPT-чат `6ae76901-f524-83eb-a2fc-73a9fbe87d0f` штатным `send_message_to_thread`, ответ прочитан через `read_thread`. Чат предложил сохранить строгий режим Q03-B и добавить явно включаемый учебный режим модельных скоростей, отдельно фиксируя исходное `unknown`, применённую расчётную скорость и источник. Его 30 км/ч и медианы по классам дорог — новые предложения, не исторически утверждённые значения. По прямому правилу пользователя ответ — рабочее решение VERIFY. Для реализации T08.07 выбран вариант без числового default: пользователь явно задаёт расчётные скорости для затронутых классов дорог; непокрытые и неоднозначные рёбра остаются unknown и блокируют T. Режим/значения — общие условия расчёта с подтверждением очистки; метрики маршрута показывают зависимость от модели. Автоматических подстановок нет. Проверить на реальных классах 170 рёбер и в сквозном сценарии T09.02.

### Q05-A/B. Референсы ограничений — ACCEPTED

Начальный фильтр: L(route)≤k_init·L_min, default k_init=3. Начальный маршрут не обязан быть втрое длиннее. L_min — минимальная длина допустимого маршрута при тех же A/B, направлениях, доступе, поворотах и закрытиях. Технически вычислять её отдельным поиском со состоянием входящего ребра; не вставлять найденный маршрут в P0. Для новичка базы L_min и T_min (минимальное время по согласованной модели), а пределы имеют вид L≤(1+δL)L_min и T≤(1+δT)T_min. Числа и место фильтрации теперь описаны рабочим Q05-C VERIFY ниже; это не прежнее утверждение пользователя. Референсы фиксируются на условия; изменение условий инвалидирует их. Отказ от оптимума для нормализации в 30–31 не отменяет эти базы. Нормализация по-прежнему от P0 или ручная.

### Q06-B. Детерминизм и конечные операции — ACCEPTED / TECHNICAL

Все случайные решения через переданный RNG; участников турнира выбирать без повторения внутри турнира, при равном J брать первого в стабильном порядке участников. По умолчанию выбран метод мутации A; B доступен переключателем. Один вызов мутации делает одну попытку; при неуспехе сохраняет исходного родителя и причину, без ремонта. На одно свободное место поколения допускается 100 полных попыток получения кандидата, а не 100 вложенных циклов каждого оператора. Скрещивание перебирает конечный список общих внутренних вершин. Улучшение для стагнации строго J_new<J_best, скрытый epsilon не вводится. Нефинитные значения — ошибка оценки. Окно стагнации и производственные случайные веса получили рабочее решение Q06-C VERIFY ниже; тестовое ядро по-прежнему принимает явную искусственную стратегию.

### Q07-B. Серия — ACCEPTED / TECHNICAL

Каждый запуск получает новый run_id, повтор одного пресета добавляет результат. Custom-веса входят в общие условия и при изменении требуют подтверждения очистки. Выбор фиксированного пресета сам по себе исключён из ключа условий и не очищает историю. Ручные масштабы по умолчанию не заполнены, все должны быть положительными конечными; произвольных defaults нет. Общая P0/общие auto-эталоны рекомендованы для сравнения, но остаются PROPOSED (33; ответ 34 относится к способу исполнения, не к P0). Даже общие эталоны не делают J разных весовых пресетов универсальной шкалой: сравнивать L, T, C и условия, J подписывать именем пресета.

### Q08-B. Сегменты — ACCEPTED / TECHNICAL

Формировать последовательные направленные цепочки по происхождению OSM way, продолжая только однозначное соединение; при ветвлении/неоднозначности разрывать цепочку. Имя само по себе не основание объединить дороги. Без имени использовать way_id. Внутри цепочки последовательно откладывать ориентир 500 м; остаток — отдельный сегмент. Не искать принадлежность по близости к соседней дороге. Пересечения хранить как интервалы вдоль исходного ребра; сравнивать вычисленные длины, при точном равенстве брать больший уровень, скрытый допуск не вводить. Отсутствие покрытия/некорректная геометрия — явная ошибка сегментации, редактирование таких рёбер недоступно до исправления. Начальное состояние и сброс — уровень 1 (свободно); рабочее значение k(1)=1 имеет статус VERIFY по Q02-C.

### Q09-B. Минимальная визуализация — ACCEPTED / TECHNICAL

Воспроизводить поколения и происхождение сохранённых особей: элита зелёная, потомки синие, мутанты фиолетовые, выбывшие серые, лучший выделен золотистым. Цвета дополнить легендой/подписями. Подробное проигрывание каждого неудачного кандидата не реализовывать: хранить все счётчики и причины, без геометрий отбракованных кандидатов. Исходное состояние — пауза на P0, после расчёта автоматически открываются результаты; скорость 1× означает одно поколение в секунду, положительный конечный множитель меняет только показ. Это технический темп UI, не коэффициент алгоритма; произвольного продуктового диапазона слайдера нет. Параметры отображения не очищают результаты.

Реализация T08.02 (4 ноября 2026): происхождение берётся только из `elite` и принятого `admission` по `child_index`. Выбывшие берутся по `retired.parents` из предыдущего полного снимка и рисуются серым пунктиром. У лучшей особи поверх широкой линии происхождения рисуется золотая линия, поэтому признак мутанта/элиты не теряется. Отклонённые `admission` без сохранённой геометрии отображаются только в счётчиках, линий для них нет.

### Q10-B. Разнообразие и счётчики — ACCEPTED / TECHNICAL

Для каждой особи E_i — множество направленных EdgeId=(u,v,key). Разнообразие D=100·[2/(N(N−1))]·Σ(i<j)(1−|E_i∩E_j|/|E_i∪E_j|), процент среднего попарного расстояния Жаккара. При N<2 D=0; для двух пустых множеств расстояние 0 (пустые маршруты всё равно запрещены валидатором). Это явно выбранная техническая метрика различий рёбер, не исторически утверждённая формула. Порядок рёбер остаётся существенным для генома/копий; формула разнообразия измеряет покрытие рёбер.

attempted — фактический вызов оператора после проверки вероятности. Успешное скрещивание — допустимый выходной кандидат, отличающийся от исходного родителя, для которого он создаётся; считать кандидатов, не пары. Успешная мутация — допустимый и изменённый геном. Возврат копии/no-op не успех. Успех оператора и принятие в популяцию — разные счётчики: успешный результат может позднее нарушить лимит копий. Отбраковка — одно отклонение кандидата на этапе приёма, со списком причин; несколько причин не увеличивают общий счётчик многократно. Неуспешная попытка оператора с допустимой копией — operator_failed, не отбраковка этой копии. Элитизм не скрещивание. Попытки генерации P0 учитывать отдельно от операций эволюции.

### Q11-B. Границы — ACCEPTED / TECHNICAL

A=B отклонить до запуска с просьбой выбрать разные вершины. Нулевые Tref/Lref и все нечисловые/нефинитные обязательные метрики — диагностируемая ошибка, не epsilon и не успех. Cref=max(1,mean(C)) остаётся согласованной формулой. При сбое после нескольких поколений сохранять полные снимки только как диагностику failed, не добавлять их как успешный результат сравнения; прежние успешные запуски сохраняются. В первой версии не вводить отдельную отмену фонового расчёта: управление воспроизведением не означает отмену вычислений; UI остаётся отзывчивым и показывает состояние. Повтор пресета описан в Q07-B.
