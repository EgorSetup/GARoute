# GARoute — подробный план реализации

**Версия:** 1.1, 2 ноября 2026 года. **Статус:** только план; ни одна задача реализации не выполнена.

**Цель:** локальное учебное приложение GARoute (Genetic Algorithm Route) в `C:\GARoute`, с собственным ГА, наглядным интерфейсом и проверенными результатами.

**Для исполнителя:** при будущей реализации использовать доступный навык `executing-plans` для последовательного выполнения; не запускать реализацию при чтении этого документа в рамках подготовки документации. Подагенты не обязательны и без отдельного основания не создаются.

**Архитектура:** [SPEC.md](SPEC.md), S02. После Git-этапа первым идёт UI-каркас. Интерфейс вызывает вычислительные модули, но ГА не зависит от NiceGUI. Используется утверждённое дерево с `algorithm/genetic/` и `algorithm/evaluation/`.

**Стек:** Python, NiceGUI/Leaflet, OSMnx, NetworkX, Plotly, pytest для проверок. Версии фиксируются после проверки совместимости. GitHub: `GARoute`, основная ветка `main`.

## Как выполнять план

- Все пути задач относительны `C:\GARoute`, если не указано иное. Создавать только файлы текущей задачи; не генерировать заранее весь проект.
- Для каждой задачи сначала записать `/цель: <ID> — <проверяемый результат>` в CURRENT_TASK.md. Если доступен инструмент целей, вести одну активную цель, завершать её только после проверок; не обещать доступность конкретной команды `/цель` в любой версии Codex.
- Задача готова к выбору, если все зависимости DONE и решены именно нужные OPEN-подпункты категории C. ACCEPTED категории A/B применять без нового вопроса. PROPOSED не является default. Ссылки Q в карточке обозначают также уже принятые решения; сверять конкретный подпункт в DECISIONS.md.
- Статусы: TODO, IN_PROGRESS, BLOCKED, DONE. Единственный реестр статусов — таблица ниже; CURRENT_TASK и PROGRESS являются кратким указателем и журналом, а не конкурирующими планами.
- Каждая карточка содержит вход/выход, конкретные изменения и проверяемый результат. Названия API ниже — предложенные контракты реализации; менять их согласованно во всех потребителях и документах, не выдавая за цитаты исходной беседы.
- Для доменной логики: подготовить содержательный тест, убедиться в ожидаемой причине неуспеха, внести минимальное изменение, выполнить целевой тест. Для компоновки достаточно визуальной проверки; не писать тесты, дублирующие расположение каждого виджета.
- DONE допускается только после проверок и обновления рабочих файлов. После этого — осмысленный коммит с ID задачи. До инициализации Git изменения этапа 0 входят в первый коммит. Force push и переписывание опубликованной истории без отдельного явного разрешения запрещены; секреты не публиковать.
- Если пользователь пока разрешил только документацию, не исполнять даже T00.01. Эти пункты относятся к будущему запуску разработки.

## Общие ограничения для всех задач

Соблюдать R01–R52 ТЗ; UI-first; конечные попытки; жёсткие запреты отдельно от штрафов; фиксированный N; без ремонта; никакого подмешанного оптимума; эффективные пробки по длине покрытия; неизменяемый снимок расчёта; честные ошибки и неизвестные данные; без скрытых неутверждённых коэффициентов.

## Особое внимание при проверке

1. Параллельные рёбра и запрет на стыке: тесты T02.04, T03.01, T05.02–T05.04.
2. Недостаточно различных допустимых маршрутов: T03.04, T06.01; не уменьшать N.
3. Перекрытие короткой части и геометрическое касание другой дороги: T07.02–T07.03.
4. Нулевые/неизвестные эталоны и признаки: T04.01–T04.05; не подменять их молча.
5. Отмена изменения после расчёта: T01.08 и T08.06; сохранить всю историю и прежние значения.

## Общие контракты данных для карточек задач

Это предлагаемые границы реализации внутри утверждённых файлов. Они нужны, чтобы исполнитель каждой задачи видел ожидаемый вход/выход, не перечитывая весь проект. Поля уточняются при задаче-владельце, изменения отражаются в CURRENT_TASK и DECISIONS; производственная архитектура сохраняется.

| Тип | Владелец | Минимальное содержание |
|---|---|---|
| EdgeId, Route | algorithm/models.py, T03.01; OSM-адаптер T02.02 | Направленная тройка u/v/key; неизменяемая последовательность таких троек |
| AreaConfig | config.py, T02.01 | Согласованные границы, параметры загрузки, без выдуманных координат |
| RoadData, RoadEdge | data/road_graph.py, T02.02 | Граф, геометрии, length_m, атрибуты/статусы, связь с OSM ways |
| TurnRules, RestrictionReport | data/restrictions.py, T03.01 (чистый контракт), T02.04 (OSM-парсер) | Запрещённые пары EdgeId, поддержанные и неподдержанные отношения |
| RouteContext | algorithm/models.py, T03.01 | RoadData, A/B, доступ/TurnRules, эффективные уровни, неизменяемые входы проверки |
| GAConfig | algorithm/models.py; defaults в config.py, T01.01 | N/E/Pc/Pm/G_max, лимиты копий/попыток, seed, мутация, турнир, стагнация, параметры генерации |
| FitnessConfig, Weights | algorithm/models.py, T01.04/T04.05 | Пресет, веса T/L/C, коэффициенты штрафов, нормализация, ограничения новичка |
| ValidationReport | algorithm/models.py, T01.01/T03.01 | valid и список кодов/сообщений причин, не только True/False |
| CandidateOutcome, PopulationResult | algorithm/models.py, T03.02/T03.04 | Успех/ошибка, кандидат или полная популяция, причины/попытки |
| Individual | algorithm/models.py, T03.02/T04.05 | ID, Route, RouteMetrics/J после оценки, происхождение/родители |
| RouteMetrics, PenaltyEvents, PenaltyBreakdown | algorithm/models.py, T04.01–T04.03 | L_m, T_s, C; события P01–P15, количества/слагаемые, неизвестные признаки |

| EligibilityReport | algorithm/models.py, T04.06 | Проверка ограничений новичка и конкретная причина несоответствия |
| OperatorOutcome | algorithm/models.py, T05.02 | Результат/исходная копия, attempted/changed/valid, причины, родители |
| OperationStats | algorithm/models.py, T06.02 | Счётчики попыток, реальных успехов, отбраковок по принятой семантике |
| GenerationResult, GenerationSnapshot | algorithm/models.py, T06.01/T06.02 | Полные N особей, номер, статистика/причины, происхождение; без геометрий отбракованных кандидатов (Q09-B) |
| RunInput, RunResult | algorithm/models.py, T06.03/T06.04 | Снимок условий/seed/версии, история, лучший результат, статус и причина остановки |

Договорённости об ошибках: ожидаемый отказ генерации возвращается как типизированный результат с причиной; непредвиденная ошибка не маскируется под «нет маршрута». Вычислительные результаты содержат конечные числа, если оценка определена. Не использовать ноль вместо отсутствующего значения. Связующие пути возвращают Route или None; после сборки полный маршрут всё равно проверяется.
