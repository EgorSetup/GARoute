# GARoute

GARoute (Genetic Algorithm Route) — локальное учебное приложение для поиска и сравнения автомобильных маршрутов. Алгоритм предлагает варианты по заданным критериям; он не гарантирует глобальный оптимум, безопасность поездки, соблюдение всех правил движения или оценку расхода топлива. Требования — [SPEC.md](SPEC.md), фактические проверки — [PROGRESS.md](PROGRESS.md).

## Установка и запуск на Windows

Нужны Python 3.12, PowerShell и доступ к OSM при первой загрузке дорог. В `C:\GARoute` выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Откройте [http://127.0.0.1:8080/](http://127.0.0.1:8080/). Сервер слушает только `127.0.0.1`; остановка — `Ctrl+C` в его окне. Проверка кода:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

В `requirements.txt` закреплены проверенные версии: NiceGUI 3.18.0, OSMnx 2.1.1, NetworkX 3.7, Plotly 7.1.0, pytest 8.4.2. Первая загрузка получает данные OSM; повторная загрузка той же области читает `data/osm_cache/`. Кэш не входит в Git. Если порт 8080 занят, освободите его или измените `port` в `main.py` и откройте соответствующий адрес.

## Сценарий демонстрации

1. Дождитесь автоматической загрузки дорог из кэша или OSM. Утверждённая область WGS84: север 60.025, юг 59.995, восток 30.415, запад 30.355; сеть OSMnx `drive`. При ошибке доступна повторная попытка.
2. Кнопками «Точка A» и «Точка B» укажите места на карте. Зелёная галочка подтверждает выбор; режим сам возвращается к «Просмотр». Недостижимая направленная пара блокирует P0.
3. Выберите пресет и нормализацию «По начальной популяции». Для короткой демонстрации можно задать N=5, E=1, 3 перехода и максимум копий 5. Нажмите «Начальная популяция» слева, затем «Расчёт». P0 остаётся общей для разных пресетов; её не требуется создавать повторно при переключении пресета.
4. Просмотрите маршрут, поколения и графики. «Лёгкий» сохраняет общую P0, но не выбирает непригодную особь итоговым победителем. Сравнивайте пресеты по L/T/C: J имеет разные веса.
5. В режиме «Пробки» ЛКМ повышает уровень сегмента, ПКМ понижает; 11 закрывает проезд по связанным рёбрам. Переключатели «Граф», «Пробки», «Маршруты», «Карта» независимо скрывают только слои карты. «Сброс пробок» возвращает исходные уровни, «Сброс настроек» — параметры панели. При наличии результатов отмена правки сохраняет историю, подтверждение удаляет зависимые результаты.

## Как устроен расчёт

`data/osm_loader.py` загружает и кэширует граф, `data/road_graph.py` нормализует направленные дороги, `data/restrictions.py` обрабатывает поддержанные запреты поворотов, `data/traffic.py` вычисляет действие пробок. Ген маршрута — полное направленное ребро `(u, v, key)`; `key` различает параллельные дороги. Особь — последовательность рёбер от A до B. `algorithm/genetic/validation.py` проверяет связность, отсутствие повторных вершин, закрытые дороги и манёвры.

`algorithm/genetic/initialization.py` формирует начальную популяцию P0 строго размера N. Турнирный отбор (`selection.py`) выбирает родителей; `crossover.py` соединяет пути по общей промежуточной вершине. Мутация A (`mutation.py`) заменяет участок между двумя вершинами; мутация B строит замену через случайную промежуточную вершину. `evolution.py` сохраняет элиту и историю каждого поколения. Недопустимый потомок отбраковывается; работающего ремонта маршрутов нет. Для заполнения каждого места установлен конечный предел попыток. `attempts_exhausted` означает отказ генерации при данных условиях, а не доказательство отсутствия пути. Популяция скрыто не уменьшается.

`algorithm/evaluation/fitness.py` вычисляет длину L в метрах, время T в секундах и наблюдаемую сложность C. Стоимость минимизируется по формуле `J = wT·T/Tref + wL·L/Lref + wC·C/Cref`: веса суммируются до 1, положительные эталоны фиксируются на весь запуск. «Быстрый» использует вес T=1, «Экономичный» — L=1; «Лёгкий» дополнительно применяет два жёстких предела относительно L_min и T_min. Наблюдаемая C не выдаётся за полную сложность при отсутствии признаков OSM: карточка перечисляет неизвестные и неподдержанные свойства.

`interface/` собирает страницу и хранит независимые результаты пресетов. `visualization/animation.py` воспроизводит рассчитанные снимки; перемотка и скорость показа не перезапускают ГА. `visualization/charts.py` строит графики сходимости, разнообразия, распределения J и операций.

## Ограничения данных и расширения

В проверенном кэше — 1685 узлов, 2431 направленное ребро и 13 неподдержанных отношений OSM. Скорость берётся из однозначного числового `maxspeed`, затем из поддержанного символического тега (`RU:urban`, `RU:living_street`). При отсутствии тега в утверждённой городской области для классифицированных обычных дорог применяется расчётное правило 60 км/ч, для `living_street` — 20 км/ч. Источник такого значения отмечен как предположение по ПДД 10.2 и OSM-классу; это не измеренная скорость и не подтверждённое индивидуальное ограничение. Неоднозначные теги и непокрытые классы сохраняют `unknown` и блокируют необходимый расчёт.

Часть рабочих коэффициентов и правил имеет статус VERIFY по ответам исходного проектного чата; они перечислены с источниками в [DECISIONS.md](DECISIONS.md) и не выдаются за отдельное утверждение пользователя.

Уровни пробки 1–11 — ручная учебная модель, а не потоковые данные. Для каждого ребра действует уровень сегмента с наибольшей длиной покрытия; при равенстве выбирается больший уровень. Уровень 11 исключает ребро. Поддерживаются простые отношения `no_*` и `only_*` через одну `via`-вершину; неоднозначные и неподдержанные ограничения отражаются в диагностике. Неполнота OSM, предел попыток и стохастический поиск не позволяют обещать расчёт для каждой пары и конфигурации.

История запусков хранится в памяти текущей страницы и не восстанавливается после её перезагрузки; дорожный OSM-кэш остаётся на диске. Ремонт недопустимых маршрутов и дополнительные сценарии дорожных условий — возможные расширения, сейчас это не работающие функции. Искусственные режимы тестирования карты и подтверждения изменений включаются только переменными `GAROUTE_MAP_EVENT_TEST=1` и `GAROUTE_CHANGE_TEST=1`; их данные не являются результатами расчёта.
